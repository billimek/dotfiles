---
description: Fold runtime Claude Code settings changes back into the nix-managed defaults
---

`~/.claude/settings.json` is generated by nix and **copied** into place on every
`nh home switch`, so anything Claude Code wrote at runtime (`/config`, `/effort`,
"add to user settings") is overwritten. The activation script stashes a timestamped
copy in `~/.claude/settings-drift/` whenever it detects such a change. Your job is
to triage those stashes and fold the keepers into nix.

## Steps

1. **Find the stashes.** `eza -1 ~/.claude/settings-drift/` — if the directory is
   missing or empty, report that there is nothing to reconcile and stop.

2. **Work out what nix currently produces**, so you compare against the right baseline:

   ```fish
   set nixgen (rg -o -m1 '/nix/store/\S+-claude-code-settings\.json' ~/.local/state/nix/profiles/home-manager/activate)
   ```

3. **Diff each stash against that baseline**, oldest first, normalising key order:

   ```fish
   diff (jq -S . ~/.claude/settings-drift/<stamp>.json | psub) (jq -S . $nixgen | psub)
   ```

   Lines marked `<` are what Claude Code had; `>` is what nix installs.

4. **Classify every difference.** Do not blanket-apply — most drift is noise:

   - **Real preference** → a key the user deliberately changed (`effortLevel`,
     `model`, `theme`, `autoUpdates`, `agentPushNotifEnabled`, a new
     `permissions.allow` entry). Candidate for nix.
   - **Normalisation noise** → Claude Code rewrites the file and drops keys whose
     value equals the default. `statusLine.padding` / `subagentStatusLine.padding`
     disappearing when set to `0` is the known example. Ignore these; nix re-adds
     them and the result is identical in behaviour.
   - **Machine-local state** → anything that is not a preference and should never
     be committed (cached tokens, per-project bookkeeping, one-off dismissals).
     Ignore. If in doubt whether a key is a preference or state, ask rather than
     guessing, since committing state would push it to every device.

5. **Apply the keepers** to `defaultSettings` in
   `modules/home-modules/claude-code.nix`. Keep the existing grouping and comment
   style. If a setting only makes sense on one host, put it in that host's file
   under `modules.claude-code.settings` instead of the shared defaults.

6. **Verify and finish:**

   ```fish
   nix fmt
   git add -A
   nix flake check
   ```

7. **Archive every stash you processed**, in the same run — do not defer this and
   do not ask first. It is a move, not a delete, so nothing is destroyed, and the
   preference is already captured in `defaultSettings` and staged in git:

   ```fish
   mkdir -p ~/.claude/settings-drift/reconciled
   mv ~/.claude/settings-drift/<stamp>.json ~/.claude/settings-drift/reconciled/
   ```

   This is what clears the yellow `cfg-drift N` indicator in the statusline, which
   counts only top-level stashes. Skipping it leaves the indicator lit after the
   work is done, which trains the user to ignore it — the exact failure this whole
   mechanism exists to prevent. A stash whose contents you decided were entirely
   noise still counts as processed: archive it too.

   Only leave a stash in place if you genuinely could not finish triaging it, and
   say so explicitly in your report.

8. Tell the user what you changed, what you deliberately skipped, and which stashes
   you archived. Let them run `nh home switch .` themselves. Mention that the
   `cfg-drift` indicator clears on the next statusline render.

## Notes

- Do not edit `~/.claude/settings.json` directly; nix owns it and will overwrite it.
- `~/.claude.json` is **not** in scope. Claude Code owns it outright (auth, project
  trust, MCP state, `lastSeenOrgDefaultUpdatedAt`) and it is machine-local.
- Per-project `.claude/settings.local.json` is not nix-managed either, so permission
  grants recorded there are already safe and need no reconciliation.
